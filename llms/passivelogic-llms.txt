# PassiveLogic

> PassiveLogic builds a physics-based autonomy platform for buildings and industrial systems: Hive, Hive Mini and Cell edge controllers, the Sense wireless sensor line, and the Autonomy Suite design-to-operate applications. Its software core is Quantum — an open, physics-based digital twin ontology developed with the U.S. Department of Energy and the Quantum Alliance consortium — exposed to developers as a GraphQL API over the twin graph, fronted by a documented HTTP REST API for identity, tenancy, devices and data export.

Generated by API Evangelist on 2026-08-04. PassiveLogic does not publish an llms.txt of its own — /llms.txt on passivelogic.com returns the Framer single-page-app HTML shell, not a document. Every link below was fetched and its status recorded.

## APIs

- [PassiveLogic REST API](https://passivelogic.com/app/swagger/): OpenAPI 3.0.1, 197 operation objects across 177 paths (~66 distinct operations published three times: unversioned, /api/v0.19 and /api/v0.20). Covers authentication, API-key issuance, account and organization management, auth groups, image and binding upload, device login/registration, Tailscale tunnel auth, CSV property-history export, health checks and GraphQL access. Base URL https://passivelogic.com/api/
- [Quantum GraphQL API](https://passivelogic.com/api/graphql): the real data plane over the Quantum digital twin graph — buildings, floors, zones, surfaces, equipment, components, properties, time series. GET and POST. Authenticated; anonymous introspection returns 401.
- [GraphQL subscriptions](https://passivelogic.com/api/graphqlSubscribe): WebSocket channel for GraphQL subscriptions (graphql-ws / graphql-transport-ws).
- [QuantumSync](https://passivelogic.com/api/quantumsync): WebSocket channel for real-time Quantum graph sync and collaboration.

## Specs

- [OpenAPI 3.0.1 (live)](https://passivelogic.com/api/doc): the machine-readable contract, served as JSON from the API host root.
- [OpenAPI (API Evangelist copy)](https://raw.githubusercontent.com/api-evangelist/passivelogic/refs/heads/main/openapi/passivelogic-rest-api-openapi.yml)
- [OpenID Connect discovery](https://login.passivelogic.com/realms/prod/.well-known/openid-configuration): Keycloak realm "prod" — authorization_code with PKCE S256, client_credentials, device_code, refresh_token, token-exchange, CIBA; DPoP and mTLS-bound tokens advertised.
- [JWKS](https://passivelogic.com/api/auth/keys): public keys PassiveLogic uses to sign its own JWTs (ES384 / P-384).

## Auth

- Long-lived API key in the `PL-API-KEY` header. Issue with `GET /api/auth/api-key/generate` as an authenticated user; revoke with `DELETE /api/auth/api-key`. A key carries the same permissions as its issuing user.
- XSRF-protected JWT in the `X-PL-AUTH` header (used by the web app).
- `GET /api/auth/login` with HTTP basic returns an authorization token and a refresh token.
- Interactive login redirects to the external Keycloak identity provider at https://login.passivelogic.com/realms/prod
- Deprecated: PL-API-KEY carried in an `Authorization` bearer header.

## Conventions and gaps

- Versioning is URI-path (`/api`, `/api/v0.19`, `/api/v0.20`); the Quantum ontology carries its own schema version.
- Errors use a custom `{"error": true, "reason": "..."}` envelope — not RFC 9457, with no machine-readable code. The published spec declares only 200 responses.
- No pagination, filtering or sorting parameters in REST — that work belongs to GraphQL.
- No idempotency key, no request-id header, no documented rate limits.
- 17 distinct operations are flagged `deprecated` in the spec, but there is no published deprecation policy and no Sunset/Deprecation headers.
- No `/.well-known/security.txt`, no A2A agent card, no MCP server, no AsyncAPI, no published SDK packages.
